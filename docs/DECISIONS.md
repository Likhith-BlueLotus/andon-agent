**ADR-018 — R-set construction rules (Phase 1 Part E)** · 2026-10-11 · accepted (data)
Context: the R-set must take truth only from the sources and still be a line stop the agent can investigate. → Decisions: (1) *Time:* the source clock is read as plant local time and shifted by whole days into Aug–Sep 2026. (2) *MetroPT-3* is 0.1 Hz: 1 Hz rows only between real samples ≤ 20 s apart, never across longer gaps (`source_gap` imperfections). Weld-cell air follows the existing regulator model driven by the mapped header (gaps bridged by hold *for the physics only*). Stop = first weld-air low alarm after the report start, else the operator rule "compressor loaded ≥ 95 % of the last 4 h" (line held at ST20). Onset = report start. (3) *UCI:* the 10 stable all-optimal cycles are looped to fill the week (no other healthy stable cycles exist); the labelled condition's cycles run once, in order, to the stop; onset = first labelled cycle. Cooler 3 % uses the rig's own warm-up cycles 0–209 (flag 1), which avoids a 20 °C step at the splice. (4) *IMS:* RMS per snapshot held at 1 Hz; bearing temperature and drive current follow the real vibration through the S-set's gains; the readme documents no onset, so `onset_ts` is **null** for R016/R017 rather than invented. (5) Agent-visible provenance names exact rows, cycles and files but **withholds labels** (UCI condition labels, the MIMII normal/abnormal folder, MetroPT source dates); labels live in `sim_meta.json` / `audio_truth.json`, never loaded. (6) All R stops are generated from visible symptoms or benign glitches; no-fault stops include air- and hydraulic-sounding glitches so the stop text alone doesn't give the answer. → Rejected: per-segment normalisation (erases 0.3–6 % shifts); repeating fault cycles to lengthen faults (invents duration); a detector-estimated IMS onset as truth (our estimate, not the source's). → Consequences: R009–R012 faults are short (10–19 min, cooler 3.7 h); R001–R003 stop on duty alone (no pressure drop), which is the real signature; the LLM may recognise public datasets from provenance names (IMS test 2, MetroPT-3), so R-set results carry a contamination caveat.

**ADR-020 — ADK model calls accounted through an App-level plugin** · 2026-10-11 · accepted (Person A)
Context: ADK agents call Gemini through their own model objects, bypassing `agents/llm.py` (RISKS #22): no pinned-model guard, no ledger, no kill switch. → Decision: `agents/adk_budget.AndonBudgetPlugin` on `App(plugins=[...])` (Runner-level `plugins=` is deprecated in ADK 2.11). `before_model`: reject unpinned models and temperature/top_p/top_k, then `spend.check()`; violations **raise** — ADK re-raises plugin errors as `RuntimeError` with the cause chained, which stops the whole run; `run_error(exc)` maps it to the SSE `error` code (`budget_exhausted`, `llm_call_limit`, `model_unavailable`, `model_timeout`, `internal`). `after_model`: book `usage_metadata` via `LLM.record()` only for non-partial responses (SSE partials also carry usage), keyed per model call by the callback context's `actions` object, booking only increases if one call yields two finals. `on_model_error`: failed ledger row (`usd: null`), error propagates. Per-run totals keyed by ADK `invocation_id` (`plugin.run_cost(inv).to_cost_data()` = `cost` payload); tools calling `LLM.generate(..., run_id=invocation_id)` land in the same totals. One shared `LLM`/`SpendTracker` per process (`agents.llm.get_llm()`). Models built with `make_model(model_id, thinking_level)` (`PinnedGemini`: location from `config.location_for`, HTTP retry on 429/5xx, thinking level + per-attempt timeout on every request). → Rejected: returning an error `LlmResponse` from `before_model` (a `SequentialAgent` just runs its next sub-agent; `end_invocation` set in a model callback does not reach the parent — verified); wrapping every agent in a custom `BaseLlm` that calls `LLM.generate` (re-implements ADK streaming/aggregation, larger surface); agent-level callbacks (easy to forget on one agent; plugins are global). → Consequences: every `App` must include the plugin (graph builder + a test); the counter is still per process (RISKS #23); a run that dies on budget surfaces as an exception, not an event, so the API wraps `runner.run_async` and emits `error` + `done`.

**ADR-021 — Live serving store: per-incident DuckDB from published Parquet in GCS** · 2026-10-11 · accepted (Person A)
Context: RISKS #24 — BigQuery tool queries take 7–16 s each; a live diagnosis makes ~15 tool calls. → Decision: `simulator.publish` uploads only agent-visible files (allow-list: telemetry/alarms/shift_notes/work_orders/provenance Parquet, `stop_event.json`, `audio_index.json`; hard deny on truth/sim_meta/audio_truth/`*label*`; JSON keys and Parquet columns checked against ground-truth field names) to `gs://<bucket>/store/v1/{scenario_id}/`, the shared tables (historical work orders, assets, spec limits) to `store/v1/_shared/`, and `store/v1/manifest.json` last (ids, set, display source label, stop station/time, sha256 + bytes; no cause, variant or truth field). `agents/store_cache.py` (`STORE_BACKEND=gcs`) downloads one scenario at incident start, verifies every sha256, builds a DuckDB through the same `simulator.load.load_duckdb` path (no fork) and serves the tools from it; LRU of `STORE_CACHE_MAX` scenarios in `STORE_CACHE_DIR`, single-flight builds, eviction never removes a scenario held by a running incident, a republished scenario is rebuilt on next use. BigQuery stays the system of record for the eval and analytics (ADR-007 holds). → Rejected: BigQuery Storage Read API + partition filter (still seconds per query, adds a dependency); baking all scenarios into the image (694 MB, image already 1.19 GB, redeploy per data change); one big DuckDB downloaded at start (cold start grows with the set, truth-free subset still needed). → Consequences: Cloud Run `/tmp` is in-memory, so the cache costs ~10 MB of RAM per cached scenario; the runtime SA needs only `objectViewer` on the assets bucket (already granted); data changes need `uv run python -m simulator.publish` (idempotent, skips unchanged objects by sha256) but no redeploy.

**ADR-022 — API service (Phase 3): replay is event-level, protection is shared through Firestore** · 2026-10-11 · accepted (Person A)
Context: Phase 3 needs a public SSE service that stays within $300. → Decision: (1) `POST /api/incidents/{sid}/investigate?mode=live|replay` streams `run_incident` (live) or `api.replay` (stored contract events with their recorded gaps, capped at 3 s, `speed` 1-4, fresh incident and work-order ids per viewer, never a model); anonymous = replay, live = `X-Demo-Passcode`. (2) The ADK run lives in a producer task merged with a 15 s heartbeat through a queue; cancelling the response cancels that task and with it the ADK run (test: real graph on fixtures stops calling the model). Errors become `error` then `done`; internals are not sent to the client. (3) Kill switch: `SpendTracker` gets `add_listener` / `add_guard` hooks (the only edit to `agents/llm.py`); `api/budget.py` mirrors every booked amount into Firestore `spend/{IST date}` with `Increment` and its guard raises `BudgetExhaustedError` from `check()`. (4) Audit is create-only in code (Firestore rules do not bind server SDKs), step payloads stored as JSON strings because Firestore forbids nested arrays. (5) Human decisions: `Decidable.decide()` on the CMMS implementations (not on the agent-facing `CMMS` protocol); Firestore does it as one batch creating `decisions/final` (fails if present) and updating `status`, so a second decision loses. Anonymous replay approvals use `demo_work_orders`. (6) Replays are seeded from real live runs via `python -m api.replay export`. -> Rejected: per-IP limits in memory only (instances multiply them); updating the audit incident doc at the end (breaks create-only; a `meta/summary` doc is created once instead); trusting the first `X-Forwarded-For` hop (client-controlled on Cloud Run). -> Consequences: the Dockerfile must ship `data/replays/`, `data/SOURCES.md` and `eval/results/latest.json`; Firestore needs a TTL policy on `ratelimit_ip.expires_at`; a client that disconnects before the first byte may leak one concurrency slot until the process restarts (one per instance, not per request).
