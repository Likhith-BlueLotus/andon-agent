**ADR-018 — R-set construction rules (Phase 1 Part E)** · 2026-10-11 · accepted (data)
Context: the R-set must take truth only from the sources and still be a line stop the agent can investigate. → Decisions: (1) *Time:* the source clock is read as plant local time and shifted by whole days into Aug–Sep 2026. (2) *MetroPT-3* is 0.1 Hz: 1 Hz rows only between real samples ≤ 20 s apart, never across longer gaps (`source_gap` imperfections). Weld-cell air follows the existing regulator model driven by the mapped header (gaps bridged by hold *for the physics only*). Stop = first weld-air low alarm after the report start, else the operator rule "compressor loaded ≥ 95 % of the last 4 h" (line held at ST20). Onset = report start. (3) *UCI:* the 10 stable all-optimal cycles are looped to fill the week (no other healthy stable cycles exist); the labelled condition's cycles run once, in order, to the stop; onset = first labelled cycle. Cooler 3 % uses the rig's own warm-up cycles 0–209 (flag 1), which avoids a 20 °C step at the splice. (4) *IMS:* RMS per snapshot held at 1 Hz; bearing temperature and drive current follow the real vibration through the S-set's gains; the readme documents no onset, so `onset_ts` is **null** for R016/R017 rather than invented. (5) Agent-visible provenance names exact rows, cycles and files but **withholds labels** (UCI condition labels, the MIMII normal/abnormal folder, MetroPT source dates); labels live in `sim_meta.json` / `audio_truth.json`, never loaded. (6) All R stops are generated from visible symptoms or benign glitches; no-fault stops include air- and hydraulic-sounding glitches so the stop text alone doesn't give the answer. → Rejected: per-segment normalisation (erases 0.3–6 % shifts); repeating fault cycles to lengthen faults (invents duration); a detector-estimated IMS onset as truth (our estimate, not the source's). → Consequences: R009–R012 faults are short (10–19 min, cooler 3.7 h); R001–R003 stop on duty alone (no pressure drop), which is the real signature; the LLM may recognise public datasets from provenance names (IMS test 2, MetroPT-3), so R-set results carry a contamination caveat.

**ADR-025 — Mandatory LOTO steps and citation premises are decided by code** · 2026-10-11 · accepted (Person A, via coordinator)
Context: live R002 on the deployed app (2026-10-11): (a) the work order had 16 of 21 compressed_air LOTO steps because the drafter model chose `safety_step_ids` and code only required one step per phase; it dropped step 16 "Test for absence of voltage at the compressor motor terminals…", an unconditional step (the recorded replay had 17/21: selection was non-deterministic). A step is conditional only when its own text states a scope: `asset` (weld_controller 7, 9, 12 "On ST30, …" → resolved by code: mandatory on ST30-WLD, not applicable on ST20-WLD) or `task` (compressed_air 7, 10 "For work on the compressor or the receiver, …"; conveyor_drive 8 "Before removing the chain or the drive shaft, …"). Sealer and press: no conditional steps. `assemble()` always inserts every mandatory step; the model may only add conditional ones; `check_safety_steps` fails a WO missing a mandatory step (drafter post-check and API approval re-check). A pinned text that no longer matches falls back to mandatory and fails `tests/test_loto_policy.py`. `loto.py` and the ADR-019 hash are unchanged. Drafter prompt v2. (2) `simulator/manuals/premises.py` pins 59 diagnostic passage fragments (as rendered, incl. the cached 6.2 background prose of the air manual) to positive measurable premises (`fall`/`rise`/`step` = a non-artefact change point in that direction; `low`/`high` = a *sustained* level beyond the normal range or an explicit value: a change point to a new level beyond it or a window mean beyond it; `loaded` = loaded-time fraction ≥ 0.8). **ADR-027 — Tool budgets are enforced by withdrawing tools, not only by refusing calls** · 2026-10-11 · accepted (Person A, via coordinator)
Context: final eval (`eval/results/final_flash`) had 5/154 graph runs (S1: S009, S019, R002, R014; S2: S044) end with `llm_call_limit` and 0 verifier iterations. Reproduced live on S009: the commander called `get_stop_event` once and `list_assets` 40 times; 38 were `budget_reached` refusals from `budget_guard`, which the model ignored, so the run hit ADK `max_llm_calls` (40) before the analyst ran. A refusal is only advice to the model. → Decisions: (1) `Runtime.tool_gate(agent, output_schema)` is a `before_model_callback` on every tool-using agent (commander, analyst, librarian, drafter). When `scope.used(agent) >= TOOL_BUDGETS[agent]` it calls `withdraw_tools(llm_request)`: `config.tools` and `config.tool_config` are cleared (only ADK's `set_model_response` declaration survives, the non-native structured-output path), the agent's `output_schema` is set via `LlmRequest.set_output_schema` if ADK had not set it, and `TOOLS_WITHDRAWN_NOTE` is appended to the system instruction. Gemini cannot call an undeclared function, so it must write the plan/report. `tools_dict` is untouched: a stray call is still answered by `budget_guard`, which runs before ADK's tool-not-found handling (verified on ADK 2.11.0). (2) Hard stop: refusals issued after tools were withdrawn are counted per agent (`scope.ignored_refusals`); the `HARD_STOP_REFUSALS`-th (3) sets `tool_context.actions.skip_summarization`, which makes the function-response event a final response, so ADK's flow loop ends that agent's turn.
